Photos carry a quiet record of where they came from — camera model, timestamp, sometimes exact GPS coordinates. Clearfile finds that record and removes it, entirely inside this browser tab. Output format

"Keep original" is byte-for-byte lossless. Converting decodes and re-encodes the image instead — it strips metadata too, but the pixel data gets recompressed, which is the tradeoff for changing format. GIF, BMP, SVG, and ICO can be read and cleaned but can't be a conversion target — no browser can encode to those from canvas. AVIF encoding isn't supported everywhere yet; if your browser can't produce it, that file falls back to a lossless clean in its original format and is noted below. HEIC likewise only decodes for conversion in browsers with native HEIC support (mainly Safari).

How this works — with "Keep original," each file's own byte structure is read directly and the metadata segments (EXIF, GPS, timestamps, author/software tags, Photoshop caption data, GIF comment/XMP blocks) are cut out at the byte level. Compressed image data is never decoded or re-encoded, so pixel quality is unchanged — this is removal, not recompression. Color profiles are left in place on purpose, since they affect how colors render rather than who took the photo. HEIC and AVIF are handled a little differently: rather than cutting the metadata item out of the container, its contents are overwritten with zeros in place, which is safer against corrupting the file — if a file's structure can't be confidently read, the original is left untouched and flagged rather than risked. BMP and ICO have no metadata format to begin with, so they pass through unchanged. SVG is handled as text, not bytes: XML comments, the spec's own <metadata> element (where Illustrator/Inkscape/Figma conventionally write creator info), embedded scripts, and Inkscape-specific attributes are stripped; visible content like <title>/<desc> is left alone since that's part of the image, not a record of where it came from.

Converting to JPEG, PNG, WebP, or AVIF instead decodes the image and re-encodes it from scratch, which also strips metadata but recompresses pixel data — the necessary tradeoff of changing format. If your browser can't produce the format you picked, that file automatically falls back to a lossless clean in its original format, and it's called out in the list rather than failing silently.

Verified, not just promised — after cleaning, each file is re-scanned with the same detector used to find the original metadata, so you see an actual "0 fields remain" result rather than a claim.
